# Aspire 13.1 Azure AD PostgreSQL Authentication Fix

**Date**: 2026-02-07
**Issue**: Deployed backend failing to connect to Azure PostgreSQL Flexible Server with Azure AD authentication

## Root Cause

Azure PostgreSQL Flexible Server was configured with:
- Azure Active Directory (Entra ID) authentication: **Enabled**
- Password authentication: **Disabled**

The API was failing with:
```
28000: no pg_hba.conf entry for host "...", user "root", database "gitclaw", no encryption
```

**Problems identified:**
1. Connection string was using "root" instead of managed identity name
2. No SSL encryption configured
3. No Azure AD token authentication configured

## Solution Overview

### 1. Added Azure.Identity Package

```bash
cd backend/GitClaw.Api
dotnet add package Azure.Identity
```

This provides `DefaultAzureCredential` for managed identity token authentication.

### 2. Updated API Program.cs

**File**: `backend/GitClaw.Api/Program.cs`

Added Azure AD token authentication for Azure deployments:

- **Detection**: Checks if connection string contains `postgres.database.azure.com`
- **Connection String Enhancement**:
  - Sets `Database = "gitclaw"`
  - Sets `Username = MANAGED_IDENTITY_NAME` (from environment)
  - Sets `SslMode = Require`
- **Token Provider**: Uses `UsePeriodicPasswordProvider` to fetch Azure AD tokens
  - Scope: `https://ossrdbms-aad.database.windows.net/.default`
  - Refresh interval: 1 hour with 10 second buffer

### 3. Simplified Managed Identity Detection

**File**: `backend/GitClaw.Api/Program.cs`

The API now uses Azure's standard environment variable `AZURE_CLIENT_ID`:
- Azure automatically sets this when a managed identity is assigned to the container
- Used as the PostgreSQL username for Azure AD authentication
- No manual configuration needed in AppHost

**File**: `backend/GitClaw.AppHost/Program.cs`

Aspire automatically handles managed identity assignment when using `.WithReference(postgres)`:
- No manual configuration required
- The managed identity is automatically assigned to the container app
- The `AZURE_CLIENT_ID` environment variable is automatically set by Azure

### 4. Fixed Port Configuration

**Files**:
- `backend/GitClaw.AppHost/Program.cs`
- `frontend/Dockerfile`

Fixed port conflict where both frontend and API were using port 8080:
- **Frontend**: Port 80 (standard HTTP)
- **API**: Port 8080 (backend service)

## How It Works

### Development Mode
- Uses local PostgreSQL container
- Standard connection string with username/password
- No Azure AD authentication

### Production Mode (Azure)
1. Aspire deploys Azure PostgreSQL Flexible Server with AD auth enabled
2. Aspire creates a user-assigned managed identity
3. Aspire assigns the managed identity as PostgreSQL administrator
4. API container is assigned the same managed identity
5. On startup, API:
   - Detects Azure deployment
   - Reads `MANAGED_IDENTITY_NAME` from environment
   - Builds connection string with SSL and managed identity username
   - Configures Npgsql to use token-based authentication
   - Uses `DefaultAzureCredential` to get Azure AD tokens automatically
   - Tokens are refreshed every hour
